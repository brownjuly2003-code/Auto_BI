# YAML: an escape that names a surrogate makes a file one that cannot be read — проверки автора

**Дата:** 2026-10-05
**Срез:** T-55; verifier 93 → 94 / check 68 → 69
**Автор:** Claude Opus 5.5 (`claude-opus-5-5`), напрямую, без MyFlow-исполнителей
**Модельное ревью:** не проводилось

Владелец в этой сессии выбрал прямое исполнение: спеку, код, тесты и доки написал Claude
Opus 5.5, MyFlow не запускался, synthetic Astra xhigh review не было. По
[ADR 0006](../adr/0006-modelled-review-development-gate.md) модельное ревью не выполнено, пока
нет фактического результата Astra xhigh, — у этого среза его нет. Всё перечисленное ниже —
проверки автора над собственной работой: не независимое ревью, не human/design-partner
acceptance и не production acceptance. Тесты и пробы прогонялись на Mac (Python 3.13.13,
3.12.13 и 3.14.6; PyYAML 6.0.3, собранный с libyaml; pydantic 2.13.4). Контракт:
[files a command cannot read](../specs/unreadable-inputs.md), седьмое требование.

Три среза подряд оставляли одну границу с разных сторон: одиночный суррогат как значение
входа. T-50 записал его как dimension validated-контракта (`ValidationError`), T-53 закрыл
два поля результата `decision investigate` схемой, T-54 насчитал 22 прогона `decision
verify` из 1200, которые кончаются исключением. Каждый раз значение чинили там, где оно
всплыло. Этот срез закрывает место, откуда оно приходит.

Double-quoted scalar YAML может назвать символ кодом — escape в 16 или 32 бита. Сканер,
которым работает `yaml.safe_load`, строит строку и из кода суррогата (U+D800–U+DFFF):
половины UTF-16-записи символа, у которой нет ни UTF-8-формы, ни формы в canonical JSON. Из
двух escape, которые JSON читает как один символ вне BMP, он строит два суррогата. libyaml
каждый такой escape отвергает (`found invalid Unicode character escape code` — проверено
`yaml.CSafeLoader` на одном escape и на паре). Что будет со строкой дальше, решал тот, кто
читал документ следующим: схема в одном поле её отвергала, в соседнем принимала; у digest
ref или прогона не было для неё формы; отчёт, называвший ею контракт, не печатался.

На HEAD `cbef9e2` снято вызовом команд в процессе: суррогат U+D800 — один и между двумя
буквами — на месте каждой строки и каждого ключа, которые держат файлы фикстуры, записанный
в файл так, как его пишет PyYAML (escape в double-quoted scalar). Файлы: продукт и metric
contract под validated paths, `model.yaml` и metric contract каждого ref, dashboard spec,
verified asset, results file, план и результат `decision investigate`. 666 мест, 1332
документа, 1934 прогона (`decision validate` и `decision verify` над validated-файлами,
`decision verify` и `decision capture` над файлами прогона, `decision investigate`).

Что стоит за числами HEAD:

- 50 исключений. `decision validate` — 12 `UnicodeEncodeError` при печати отчёта в поток,
  кодирующий UTF-8: escape на месте `kind` или `id` контракта и на месте dimension scope
  продукта. `decision verify` — 38: `CanonicalizationError` в 18 (dimension scope продукта;
  `kind` и `id` validated metric contract; заголовок дашборда, id и заголовок чарта;
  окружение и исполнитель аттестации) и `ValidationError` в 20 (dimension и ключ grain
  validated metric contract — схема `SemanticGap`; `unit` колонки и текст ячейки в ожидаемом
  и в записанном результате — схема `ResultDifference`).
- 4 прогона `decision validate` с exit 0: metric contract с escape на месте ключа grain
  прошёл валидацию; `decision verify` над теми же файлами кончался `ValidationError`.
- 464 оценённых прогона: 4 с exit 3 и 460 с exit 4. Из них 20 — bundle `decision verify`
  над файлом прогона, где схема приняла строку: dashboard spec (8, exit 4), verified asset
  (2 — exit 3, 4 — exit 4), recorded results (2 — exit 3, 4 — exit 4). Остальные —
  контракты: схема отвергла строку или приняла её, и контракт оценён таким, каким его
  построил PyYAML.
- 124 прогона `decision capture` до движка: 112 — metric contract candidate ref, 12 —
  verified asset, где схема приняла строку.
- 1292 отказа с exit 2 дал тот, кто встретил строку первым, — схема, граф ref, отсутствие
  продукта; об escape в них ни слова.

Теперь общий загрузчик (`load_yaml_document` в `auto_bi/yaml_document.py`), которым YAML
читает каждая decision-команда, отвергает документ, один из скаляров которого держит
суррогат, — до того, как из документа что-либо построено.

- Отказ — `SurrogateEscapeError`: `yaml.MarkedYAMLError` без причины, с problem `found an
  escape that names a surrogate` и позицией начала скаляра — его открывающей кавычки либо
  тега или якоря перед ней. Каждый читатель уже отвечает на `yaml.YAMLError`, поэтому ни
  один из них не менялся.
- Отвергается каждый код от U+D800 до U+DFFF: названный escape в 16 или в 32 бита, строчными
  или заглавными цифрами, один или среди других символов; в значении, ключе, элементе списка
  и скаляре, который и есть документ. Соседние коды U+D7FF и U+E000 читаются.
- Пара escape, которую JSON читает как один символ, отвергается так же: PyYAML строит из неё
  два суррогата, и загрузчик ничего не склеивает.
- Из нескольких таких скаляров назван первый в порядке документа: ключ раньше значения,
  запись mapping раньше следующей, элемент раньше следующего, содержимое записи раньше
  записи после неё.
- Узел, который повторяют alias, просмотрен один раз и назван там, где стоит его якорь:
  документ, который держит сам себя, читается, а документ, чьи alias умножают его узлы,
  просмотрен за столько шагов, сколько узлов называет его текст.
- Текст, который PyYAML отвергает сам (не сканируется, не разбирается, не компонуется),
  отвергается как прежде — класс и позиция его: документ сначала компонуется, потом
  просматривается. Из отвергнутого документа ничего не строится, поэтому значение рядом с
  escape, которое не построилось бы (дата, которой нет; `!!binary` не base64; чужой тег;
  ключ-список), ответ не меняет.
- Буквы escape там, где сканер ничего не заменяет, — текст: в одинарных кавычках, в plain
  scalar, в block scalar, после экранированной обратной косой черты, в комментарии. Символ
  вне BMP читается сам и своим escape в 32 бита.
- Читатели отвечают как на текст, отвергнутый PyYAML. Файл под validated paths — один issue
  `contract.unreadable`, block, сообщение `cannot read contract: SurrogateEscapeError`;
  `decision validate` печатает отчёт. Metric contract semantic ref — один gap
  `gap.contract_invalid`, block, причина `metric contract cannot be read:
  SurrogateEscapeError`, digest байтов файла. `model.yaml` ref, dashboard spec, verified
  asset и results file — usage error `decision verify` и `decision capture`: `cannot read
  <файл>: SurrogateEscapeError at line <n>, column <m>`, exit 2, до грейда, до вопроса
  движку и до записи. План и результат `decision investigate` — та же usage error, каталог
  вывода не создан.
- Запечатанный finding называет только класс. Строка usage error называет место и ничего
  из файла не цитирует. Собственный текст отказа показывает строку файла, как текст ошибки
  PyYAML, и ни в finding, ни в строку не попадает.

Версии evidence: `VERIFIER_VERSION` 93 → 94, `CHECK_VERSION` 68 → 69. Прогон над таким файлом
давал bundle там, где схема приняла строку или отвергла её, и теперь даёт другой или
никакого; `contracts.validate` и `semantic.gaps` блокируют файл, который правило 68 оценивало
как контракт, построенный PyYAML. Historical bundles не переписаны.

Выбор. Границу называли срезы T-50, T-53 и T-54; срез выбрал оркестратор, Astra-выбора по
ADR 0006 для него нет. Решения внутри среза — тоже автора:

- Отказ стоит в общем загрузчике, а не в каждой схеме. Схем, графов и digest много, и каждое
  новое поле было бы новым местом, где строку надо не забыть отвергнуть; файл — один вход.
- Пара суррогатов не склеивается в символ. PyYAML даёт два суррогата, libyaml не даёт
  ничего; загрузчик, который прочёл бы пару как символ, стал бы третьим прочтением того же
  файла. Файл с парой — нечитаемый, пока символ не записан сам или escape в 32 бита.
- Место — начало скаляра. У узла PyYAML есть отметки начала и конца, отметки escape внутри
  скаляра нет; пересчитывать её по тексту значило бы повторить сканер.
- Класс — `yaml.MarkedYAMLError`: `unread_reason` уже печатает его класс и позицию, а
  finding уже берёт только класс.
- Слои за загрузчиком не разобраны. Схемы пятого требования, граф и digest ref, ключ
  recorded result, identity прогона отвечают на такую строку по-прежнему: её может подать
  читатель, который не этот загрузчик. Их тесты оставлены и подают строку мимо загрузчика
  (`_past_the_loader` в `tests/test_unreadable_run_inputs.py`).
- Версии подняты, хотя большинство прогонов меняет только текст usage error: 4 прогона
  `decision validate` переходят из pass в block, а findings о контрактах меняют код.

Границы. Одиночный суррогат больше не приходит из YAML-файла, но приходит иначе. JSON
называет его тем же escape, и `json.loads` его строит: проба над записанным bundle, escape
по очереди в семи текстовых полях manifest — `decision evidence` отвечает
`evidence.manifest_invalid` и exit 4, текстом и с `--json`; в двух артефактах —
`evidence.digest_mismatch`; план запроса, который движок отдаёт текстом, и dbt manifest
v1-импорта не спрашивались. Аргумент командной строки берётся как передан: `decision
capture` с суррогатом в `--environment` исполняет запрос, выходит с 0 и пишет в файл escape,
а `decision verify` над этим файлом теперь отвечает `cannot read <файл>:
SurrogateEscapeError at line 19, column 22` (на HEAD — `CanonicalizationError`); capture
по-прежнему пишет файл, который verify не прочтёт. v1-загрузчики читают YAML сами и не
тронуты: `SemanticModel.load` (им читают модель v1-команды), `auto_bi/auth.py`, `load` у
`MetricContract` и `DecisionProductSpec` (в пакете их никто не вызывает). Слои за
загрузчиком держат свой ответ на такую строку только тестами, которые подают её мимо
загрузчика. Пара escape не склеивается: файл, который так выгрузил какой-нибудь writer,
нечитаем, пока символ не записан сам или escape в 32 бита. Названо место начала скаляра, а
не escape: в скаляре из нескольких строк escape может стоять ниже; из нескольких скаляров
назван только первый. Контракт с таким escape там, где схема принимала строку, оценивался
как построенный PyYAML контракт — 4 прогона `decision validate` из 120 над metric contract
фикстуры проходили и теперь блокируются. `decision capture` идёт к движку с metric contract
candidate ref, который не прочитан (120 прогонов из 120), как шёл на HEAD там, где схема
контракта отвергала строку (112): gap принадлежит snapshot, а capture ничего не грейдит.
Побочная проба нашла 4 необработанных исключения из 1904: таблица модели (base или
candidate) с пустым именем принята схемой модели и отвергнута при сравнении двух snapshots
— на первой таблице это `ValidationError` схемы `SemanticChange` внутри `run_gate`. Ключ
recorded result при чтении файла не проверяется: результат под ключом, который не id ни
одного asset (слово, число), рядом с результатом прогона прочитан и никем не спрошен;
результат прогона только под таким ключом оставляет asset без результата
(`results.reconcile` — review, `provenance.no_results`). То, что команда печатает, идёт в
поток, который отвергает символ, которого не кодирует: поток UTF-8 теперь принимает всё,
что печатают семь требований, а проба с ASCII-потоками и фикстурой в каталоге с кириллицей
в имени кончается `UnicodeEncodeError` — у `decision validate`, когда issue называет файл;
у `decision verify` при печати проверок, на детали с символом параграфа, когда use case уже
вернул отчёт, и до любой записи, когда строка usage error называет файл. Проба мест
покрывает строки и ключи, которые держат файлы фикстуры: поле, которого в фикстуре нет, ею
не спрошено. Windows: тесты там не запускались. BI и DWH не запускались: проверка offline.
Независимого ревью у среза нет — ни модельного, ни человеческого.
