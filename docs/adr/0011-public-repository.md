# ADR 0011: код форка — в публичном репозитории baseline

**Статус:** Accepted
**Дата:** 2026-11-10
**Основание:** решение владельца 2026-11-10 — выложить форк на GitHub в существующий публичный
репозиторий `brownjuly2003-code/Auto_BI`, новый не создавать; ветка `main`, без force push;
вся история форка, имя владельца убрать из текущего дерева; описание репозитория — под
DecisionOps. Заменяет пункт 1 [ADR 0009](0009-local-package-identity-no-publication.md); новая
работа после финишной черты — по пункту 4 [ADR 0010](0010-finish-line.md).

## Контекст

ADR 0009 оставил форк без публикации и без remote. Baseline v0.5.0 лежит в публичном
репозитории `brownjuly2003-code/Auto_BI`. Его `main` — merge PR #74, и по содержимому он
совпадает с точкой ответвления форка (`b4bfa1d`). В репозитории открыт PR #99: в LICENSE,
`pyproject.toml` и двух комментариях имя владельца заменено именем аккаунта. `main` защищён
ruleset: изменения — только через pull request, шесть обязательных проверок (тесты, pip-audit,
сборка образа, интеграционный стенд, gitleaks, CodeQL), без force push и без обхода.

## Решение

1. **Код форка — в `main` репозитория baseline.** Remote `origin` —
   `https://github.com/brownjuly2003-code/Auto_BI`. GitHub `main` и ветка PR #99 влиты в форк
   merge-коммитом, поэтому форк продолжает историю `main`: история baseline и теги
   `v0.2.0`…`v0.5.0` сохраняются, force push не нужен. В `main` код попадает pull request'ом из
   ветки `decisionops` с обязательными проверками ruleset.
2. **Публикуется вся история форка.** Перед push gitleaks с конфигом проекта проверяет все
   коммиты форка. В текущем дереве имя владельца заменено (PR #99), имя хоста и домашние пути
   в документах — нейтральные. Прошлые коммиты не переписываются.
3. **Перед push — полный `ci_local`** на публикуемом коммите: PASS или INCOMPLETE с названными
   непокрытыми шагами. Обязательные проверки GitHub — второй, независимый прогон.
4. **Пакет не публикуется.** Нет ни PyPI, ни образа, ни тега `v0.6.0`: `release.yml` на тег
   `v*.*.*` выпустил бы DecisionOps под именем `autobi-agent`, которое на PyPI занимает
   baseline. Пункты 2–4 ADR 0009 в силе: имя `autobi-agent`, версия `0.6.0`, без
   `[project.urls]` — ссылки нужны индексу пакетов, а в индекс пакет не идёт.
5. **Описание и топики репозитория называют DecisionOps.**

## Последствия

- Главная страница репозитория — DecisionOps; baseline v0.5.0 доступен по тегу `v0.5.0` и как
  опубликованный пакет.
- `pip install autobi-agent` по-прежнему ставит baseline `0.5.0`; DecisionOps запускается из
  checkout: `uv sync`, затем `uv run auto_bi`.
- Push в `main` запускает workflow репозитория. Коммит coverage-бейджа из CI ruleset не
  пропускает (так задумано в `ci.yml`), поэтому бейдж обновляется вместе с кодом. Live-sentinel
  без секретов провайдеров пропускается.
- Следующие изменения тоже идут через pull request. Бэкап git bundle остаётся.
- Публикация пакета, тег или новое имя — новое решение владельца и новый ADR.
