# Model declarations: a table declared with no name is a gap, not a table — проверки автора

**Дата:** 2026-10-05
**Срез:** T-56; verifier 94 → 95, check 69 → 70
**Автор:** Claude Opus 5.5 (`claude-opus-5-5`), напрямую, без MyFlow-исполнителей
**Модельное ревью:** не проводилось

Владелец в этой сессии выбрал прямое исполнение: спеку, код, тесты и доки написал Claude
Opus 5.5, MyFlow не запускался, synthetic Astra xhigh review не было. По
[ADR 0006](adr/0006-modelled-review-development-gate.md) модельное ревью не выполнено, пока
нет фактического результата Astra xhigh, — у этого среза его нет. Всё перечисленное ниже —
проверки автора над собственной работой: не независимое ревью, не human/design-partner
acceptance и не production acceptance. Тесты и пробы прогонялись на Mac (Python 3.13.13,
3.12.13 и 3.14.6). Контракт:
[what a model declares that the canonical graph cannot hold](specs/model-declarations-snapshot.md).

Предыдущий срез оставил границу, найденную побочной пробой: таблица модели с пустым именем
принята схемой модели и отвергнута при сравнении snapshots. Canonical graph называет таблицу
именем, которое даёт ей `model.yaml`: имя — id таблицы, первая часть id каждого её поля и
то, чем semantic diff называет изменение любого из них (`SemanticChange.subject`, не короче
одного символа). Схема модели — схема v1 — берёт для имени любой текст. Таблица с `name: ""`
входила в граф таблицей с пустым id и полями `.<колонка>`, и изменение такой таблицы diff
назвать не мог.

На HEAD `227f30f` воспроизведено вызовом `decision verify` в процессе над прогоном, который
без правки проходит. Правка модели — до записи asset'а и результата, так что аттестация
результата относится к candidate как он записан. 11 прогонов: первая или вторая таблица
фикстуры без имени — в base, в candidate, в обоих одинаково, в обоих с разным описанием
(8 прогонов); ещё одна таблица без имени, с одной колонкой и physical facts, — в base, в
candidate, в обоих (3 прогона).

| Исход `decision verify` | HEAD | Рабочее дерево |
|---|---|---|
| исключение, которое никто не ловит (`ValidationError` для `SemanticChange`) | 8 | 0 |
| exit 4, `block` | 2 | 11 |
| exit 0, `pass_with_advisory` | 1 | 0 |

Что стоит за числами HEAD:

- Исключение — в каждом прогоне, где refs в такой таблице расходятся: один её называет, а
  другой нет (`_diff_tables`, 6 прогонов), или оба держат её с разным описанием
  (`_diff_table_attrs`, 2 прогона). Ни отчёта, ни bundle.
- Два прогона с exit 4 — refs держат одинаково первую или вторую таблицу фикстуры без
  имени. Блокировали их не эта таблица, а последствия: метрика и join называют поля по
  настоящему имени, которого в графе нет.
- Прогон с exit 0 — оба ref с одной и той же лишней таблицей без имени: `semantic.gaps`
  отвечал `both snapshots represent their source completely`, в графе стояла таблица с
  пустым id.

Теперь (`_build_graph` в `auto_bi/semantic/gateway.py`):

- Таблица модели, чьё имя — пустой текст, в граф не входит: ни узла таблицы, ни узлов полей
  её колонок. Snapshot несёт на каждую такую таблицу gap `gap.table_unnamed` (block) по
  адресу `tables.<индекс>.name` — индекс с нуля, место таблицы в `tables` модели — с причиной
  `table is declared with no name: it and its <n> column(s) are not in the graph` и без
  `source_value_ref`.
- Больше о такой таблице ничего не читается: `gap.missing_physical` для неё нет; описание,
  grain, classification, колонки и physical facts canonical digest не двигают. Digest равен
  digest той же модели без этой таблицы, gap стоит на месте таблицы среди gaps таблиц.
- Join к колонке такой таблицы — join с endpoint'ом, который не объявленное поле:
  `gap.dangling_join` по прежнему правилу.
- `TableNode.id` не бывает пустым текстом (`min_length=1`).
- Гейт не менялся, кроме версий: `semantic.gaps` грейдит gap как любой блокирующий, gap не
  входит в `UNTRUSTWORTHY_GAPS`, и snapshots по-прежнему сравниваются. Gap, который несёт
  один из двух, — изменение `gap.appeared` (block) или `gap.resolved` (advisory) по адресу
  gap; таблица, потерявшая имя, — ещё и `table.removed` под именем, которое даёт ей base.

`VERIFIER_VERSION` 94 → 95, `CHECK_VERSION` 69 → 70: прогон над двумя ref, которые держали
такую таблицу одинаково, давал bundle и теперь даёт другой (другой canonical digest, другой
вердикт в третьей строке таблицы). Historical bundles не переписаны.

Выбор. Границу назвал срез T-55; срез выбрал оркестратор, Astra-выбора по ADR 0006 для него
нет. Решения внутри среза — тоже автора:

- Gap, а не usage error. Модель прочитана и принята своей схемой; чего граф не может
  держать, по принципу 6 архитектуры становится названным gap, и прогон оценивается.
  Usage error оставил бы оператора без отчёта и bundle о ref, который в остальном читается.
- Таблицы в графе нет вовсе, а не «есть под условным именем». Любое имя, которое гейт
  придумал бы сам, могло бы совпасть с настоящим и дало бы diff субъект, которого нет в
  файле.
- Адрес — место в файле, а не имя: имени нет. Индекс считается по всем таблицам модели, так
  что оператор находит запись в `model.yaml` счётом.
- Block, а не review: таблица, о которой граф ничего не знает, — дыра того же рода, что
  dangling join.
- Gap не добавлен в `UNTRUSTWORTHY_GAPS`: граф без этой таблицы — правдивая проекция
  остального, diff и impact по нему стоит читать, а сам gap уже блокирует.
- Схема v1 (`auto_bi/semantic/model.py`) не тронута: её читают v1-команды, и правило «v1
  без функциональных изменений» в силе.
- Без имени — только пустой текст. Имя из пробелов движок может принять (quoted
  identifier), и гейт о движке здесь не спрашивает.

Проверки автора — на рабочем дереве среза, на Mac:

- Факты о HEAD сняты пробой до реализации и повторены на обоих деревьях после неё (таблица
  выше).
- Новый модуль `tests/test_unnamed_table.py` — 35 тестов. Он не импортирует ничего, чего
  нет на HEAD, поэтому red снят на HEAD с этим одним модулем: 31 failed / 4 passed. Зелёные
  на HEAD — тесты границ: имя из пробелов остаётся именем, refs с такой таблицей,
  записанной одинаково, не различаются (2 случая), те же refs без неё проходят. На рабочем
  дереве модуль — 35 passed на Python 3.13.13, 3.12.13 и 3.14.6.
- Ручные мутанты — 21: таблица строится после своего gap; остаётся в графе под пустым
  текстом вместе с gap; пропущена молча; её колонки остаются полями; у неё спрошены
  physical facts; gap — review или advisory; место считается с единицы, по имени, по числу
  gaps или по числу построенных таблиц; имя из пробелов — не имя; причина без счёта колонок
  или со счётом таблиц; другой код gap; gap впереди более ранних; gap со ссылкой на
  значение; названа только первая такая таблица; узел таблицы с пустым id; версии verifier
  и check прежние. Убиты все 21 с первого прогона.
- Проба границ на обоих деревьях: колонка с пустым именем (в candidate, в base, в обоих) —
  3 прогона оценены, exit 4, одинаково на HEAD и на рабочем дереве; имя таблицы из одного
  пробела (в candidate, в обоих) — 2 прогона, так же; `decision capture` над candidate с
  таблицей без имени — 3 прогона из 3 исполняют запрос и пишут файл, как на HEAD.
- Контроль на tracked pilot-пакетах: 10 прогонов `decision verify` на HEAD и на рабочем
  дереве. Вердикт, статус и каждая проверка совпадают во всех десяти; `run_id` и digests
  другие, потому что версии evidence входят в ключ прогона.
- Ruff, Black и strict mypy чистые; концы строк новых и изменённых файлов — LF.
- Полный offline gate с duckdb на итоговом дереве, Python 3.13.13: 5387 passed,
  4 skipped, 38 deselected, exit 0. Полный набор под 3.12.13 и под 3.14.6 — те же
  5387 passed, 4 skipped, 38 deselected.

Границы. Без имени — только пустой текст: имя из пробелов и имена, которые отличаются
регистром или пробелами, — имена. Колонка с пустым именем остаётся полем `<таблица>.` графа:
её id не пуст, и изменение названо. Таблица, колонка или join, объявленные моделью дважды,
этим срезом не названы: граф держит оба объявления, а diff сравнивает по последнему.
`decision capture` замораживает candidate ref, чтобы аттестовать результат, и gaps не
грейдит: над candidate с такой таблицей он исполняет запрос и пишет файл, а блокирует гейт,
который этот результат читает. v1-команды читают `model.yaml` своей схемой, и она
по-прежнему принимает таблицу без имени. Gap в base блокирует так же, как gap в candidate
(прежнее правило `semantic.gaps`): релиз, который возвращает таблице имя, блокируется, пока
base его не получит. Windows: тесты там не запускались. BI и DWH не запускались: проверка
offline. Независимого ревью у среза нет — ни модельного, ни человеческого.
